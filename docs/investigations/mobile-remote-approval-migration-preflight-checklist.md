# 모바일 원격 승인 — 0219/0220 Migration Preflight 최종 보고서

본 문서는 **Independent Security & Failure Reviewer**로서 실제 데이터베이스 마이그레이션(`0219`, `0220`) 반영 전 안정성 및 롤백성, 라이브 가용성을 종합 점검한 Preflight 보고서입니다.

---

## 1. 0219 / 0220 분석 및 데이터 영향도
* **컬럼 구조**: 추가되는 컬럼은 모두 `nullable`이며, 기본값(`DEFAULT`)이나 `NOT NULL` 제약 조건이 선언되지 않아 기존에 존재하는 수천 건의 데이터에 영향이 없습니다.
* **백필 및 잠금 위험 (0219)**:
  - `0219` 마이그레이션 내에서 구버전 `pending` 승인들에 대한 `task_fingerprint` 백필 및 15분 소급 만료 처리가 수행됩니다.
  - 레코드 수가 적어 락이 발생하는 시간은 수 밀리초 내외로 무시할 수 있는 수준입니다.
* **마이그레이션 의존성**: `0219`에서 핵심 컬럼들이 생성되어야 `0220`의 외래키 연동 테이블(`approval_action_idempotency_keys`) 생성이 가능하므로, **`0219 ──> 0220`** 순서가 강제됩니다.

---

## 2. 기존 Pending Approval 영향 분석
* **소급 만료**:
  - 마이그레이션 즉시 15분 이상 경과한 모든 기존 pending 승인은 만료(`expired` $\rightarrow$ 410 Gone) 상태가 되어 신규 에이전트 구동 시 오작동이 원천 예방됩니다.
  - 마이그레이션 당시 활성화(진행) 중이었던 작업 중 15분이 지나지 않은 승인은 지문만 유지된다면 정상 실행됩니다.

---

## 3. 백업 및 롤백 계획

### 백업 범위 및 검증
* **백업 대상**: NEXORA PostgreSQL 인스턴스 전체 (`db_nexora`).
* **실행 명령**: `pg_dump -h <host> -U <user> -F c -b -v -f nexora_preflight_0219.dump db_nexora`
* **성공 검증**: 백업 파일 크기가 0이 아님을 확인하고, `pg_restore --list`로 스냅샷 복원이 정상 조회되는지 메타데이터 확인.

### 롤백 시나리오
1. **코드 롤백**: 오류 감지 시 애플리케이션 코드를 구버전으로 롤백합니다. 구버전 코드는 새로 추가된 `0219/0220` 테이블/컬럼을 참조하지 않으므로 문제없이 작동합니다.
2. **스키마 롤백**:
   - `DROP TABLE "approval_action_idempotency_keys";`
   - `ALTER TABLE "approvals" DROP COLUMN "expires_at", DROP COLUMN "task_fingerprint", ... ;`
3. **데이터 롤백 한계**: 소급 적용(ExpiresAt 백필)된 값은 롤백 후 원복이 불가하나, 코드상 기각(410) 상태에서 단순 취소(Cancelled)와 유사하게 취급되므로 비즈니스 논리상 치명적인 손실은 발생하지 않습니다.

---

## 4. 최종 배포 순서 확정
```
[백업 실행] ──> [DB 0219 적용] ──> [DB 0220 적용] ──> [Application 배포 및 기동] ──> [E2E 검증]
```
- **순서 근거**: 신버전 코드가 실행 직후 하트비트 루프에서 DB 컬럼을 쿼리하므로, 무조건 **DB 마이그레이션이 코드 기동보다 선행**되어야 합니다.

---

## 5. 최종 E2E 검증 시나리오 명세 (라이브)
* **모바일 승인 사이클**: 승인 생성 $\rightarrow$ PWA 화면 조회 $\rightarrow$ WebAuthn 생체인증 $\rightarrow$ API 승인 처리 $\rightarrow$ 에이전트 실행 연결.
* **만료 및 지문 거부 사이클**: 15분 카운트다운 완료 후 410 Gone 오류 검증, 태스크 텍스트 변경 후 실행 재개 시 409/410 재검증.
